# 热处理数字孪生大屏商业化改造计划

## 产品边界与方向判断

当前方向是正确的：产品应该聚焦“现场状态的可信三维呈现、设备下钻巡检和低代码大屏编排”，而不是重新建设排产、MES 或工艺执行系统。

`C:\Users\27323\OneDrive\Desktop\排产` 及客户现有生产系统继续作为批次、配方、产量和生产履历的事实来源。本项目通过外部业务数据只读适配层读取这些数据，用于大屏展示、趋势和巡检上下文；大屏不写回批次、不下发工艺、不控制 PLC。这样既能保持系统边界清晰，也能避免两个系统对同一生产事实产生冲突。

## 已完成的商业交付底座

### 1. 展示和低代码链路

- 工厂/车间/产线/设备层级和可拖拽空间布局。
- 设备四阶段巡检：实体视图 → 外壳透视 → 内部拆解 → 部件详情。
- 模型库可配置外壳节点、阶段镜头、关键部件、拆解偏移、说明和实时点位绑定。
- 低代码设计器支持四种设备视角、部件详情面板、实时点位和外部业务摘要组件。
- Unity 与后台通过上下文传递 `inspectionStage`、`partId`、部件说明和点位列表，部件详情不再依赖硬编码页面。

### 2. 外部业务数据只读契约

外部数据库适配层只允许参数化 `SELECT/WITH` 查询，拒绝多语句、写入和 DDL。标准区块如下：

| 区块 | 读取内容 | 用途 |
| --- | --- | --- |
| 批次与配方 | 批次、工序、工艺执行状态 | 设备视角右侧摘要、批次详情 |
| 温度/碳势合规 | 实际值、设定值、上下限、采样时间 | 合规曲线和异常提示 |
| 能耗 | 批次/设备/时间段能耗 | 单批次能耗摘要 |
| 停机与 OEE | 开动率、停机、产量、质量 | 产线和设备统计 |
| 维护记录 | 保养、维修、工单状态 | 设备部件详情和维护提示 |

客户表名或字段不同的时候，通过连接配置和字段映射适配，不在大屏数据库中复制生产事实。缺失表会显示“未提供该类标准数据表”，不会用模拟值冒充真实数据。

### 3. 现场可靠性

- 统一产品/配置/设计器/业务契约版本。
- `/api/health`、`/api/version`、`/api/acceptance-report` 提供真实运行状态；Unity 未连接时不宣称大屏已就绪。
- SQLite/MySQL 自动备份、整站灾备 ZIP、外部 U 盘/NAS 镜像、哈希校验、失败回滚。
- 桌面后端异常自动重启、健康探测、日志切卷、原生宿主父进程退出清理。
- 默认回环监听、严格 CORS、管理写入保护、上传路径校验和只读业务 SQL 防护。
- 离线 Ed25519 许可证：客户、有效期、功能和安装实例校验；强制模式下许可证失效会保护配置写入，但保留状态读取、替换许可证和安全退出能力。
- 离线升级清单：签名、SHA-256、最低支持版本和降级拒绝；升级前先做整站灾备，升级后自动验收。

## 交付阶段和验收门槛

### P0：可运行（已完成）

门槛：安装包启动、后端健康、数据库可连接、Unity/浏览器入口可用，日志和异常退出有迹可循。

### P1：可配置（已完成）

门槛：现场工程师可以按“系统 → 车间 → 产线 → 模型 → 设备 → 编排 → 点位 → 画面 → 验收”完成配置；所有未保存布局有醒目提示，产线位置待定时能从车间布局画布补放。

### P2：可展示（已完成）

门槛：示范现场可完成四阶段设备下钻，部件详情能带出实时点位和说明；外部批次、合规、能耗、OEE、维护区块能以只读方式显示，并明确区分“无连接”“缺少标准表”和“读取失败”。

### P3：可交付（当前代码已具备，需现场签收）

门槛：

1. 交付方配置客户许可证公钥和签名许可证，打开强制授权并验证过期/篡改行为。
2. 导出整站灾备到外部介质，在备用电脑完成恢复演练。
3. 使用签名升级包完成一次升级、自动验收和上一版回滚演练。
4. 按客户真实 PLC 型号、网络、Unity 显卡和外部排产库字段完成现场验收。
5. 记录首屏时间、设备点击响应、WebSocket 延迟、Unity 帧率和连续运行 72 小时结果。

## 接下来只做与数字孪生相关的增强

1. 建立更多热处理设备模板和客户字段映射包，但模板默认只读，不直接下发控制命令。
2. 为业务摘要增加时间范围、设备/产线筛选和“数据更新时间”标记，避免把低实时数据误解为 PLC 实时值。
3. 增加现场验收报告导出（JSON/PDF）和问题闭环编号，报告引用健康、版本、备份和 Unity 连接证据。
4. 完成 Windows 企业代码签名证书接入和安装包发布流水线；证书由交付方保管，不写入仓库。
5. 采集匿名性能指标（可关闭），持续跟踪大屏卡顿、WebSocket 重连和外部数据源失败率。

## 明确不纳入本产品核心范围

- 排产算法、工艺配方编辑、批次状态写回、PLC 控制写入。
- 代替客户现有 MES/ERP/质量系统的主数据管理。
- 未经现场确认就把模拟数据、缺失业务表或 Unity 离线状态显示成“正常”。

## 当前判断

代码已经达到“可做试点和现场交付”的商业化底座，方向无需改变；真正从试点走向规模化的关键不在继续堆业务功能，而在客户现场的真实数据库字段映射、PLC/Unity 兼容性、72 小时稳定性、代码签名和标准化交付包。每个客户项目都应以只读数据契约、模板包和验收报告收口。
