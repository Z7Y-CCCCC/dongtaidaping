# 外部业务数据只读接入

本系统的产品边界是数字孪生大屏。排产、批次、工艺、统计和维护等业务记录继续由外部软件负责，本系统只通过只读连接读取并展示，不向排产系统写入生产业务数据。

## 接入步骤

1. 在后台“系统设置 → 数据通路 → 外部数据源”新增排产系统数据库。
2. 连接类型选择 `MySQL`（排产系统默认配置为 `127.0.0.1:3307/js_robot`）。
3. 使用排产系统创建的只读数据库账号，不要复用生产管理员账号。
4. 点击测试连接，确认连接成功后记录数据源 ID。
5. 在大屏设计器或运行页使用业务数据 API，将该数据源 ID 作为 `connection_id`。

## 标准数据契约

所有接口返回 `readOnly: true` 和 `contractVersion`。业务数据读取失败时会返回 `available: false`，大屏应显示“暂无外部数据”并保留实时设备画面，不应将缺失数据显示成 0。

| 区块 | 排产系统表 | 当前展示内容 |
| --- | --- | --- |
| 批次与工艺执行 | `produce_batch`、`produce_batch_step` | 批次号、产品、操作员、状态、进度、工件数量、工艺步骤和炉号 |
| 温度/碳势曲线 | `rc_furnace_attr_history` | 按设备/批次读取历史信号；按信号名称筛选温度、碳势 |
| 设备运行统计 | `device_statistics_daily` | 运行、空闲、报警、离线分钟数、批次数、利用率 |
| 单批次能耗 | 预留 `energy_consumption`、`energy_consumption_daily`、`batch_energy` | 外部库未提供标准表时明确返回不可用 |
| 维护记录 | 预留 `maintenance_record`、`maintenance_order`、`maintenance_log`、`repair_order` | 外部库未提供标准表时明确返回不可用 |

## API

```text
GET /api/business-data/manifest?connection_id=schedule_readonly
GET /api/business-data/snapshot?connection_id=schedule_readonly&device_id=FURNACE-01&limit=50
GET /api/business-data/batches?connection_id=schedule_readonly&device_id=FURNACE-01
GET /api/business-data/batches/101?connection_id=schedule_readonly
GET /api/business-data/compliance?connection_id=schedule_readonly&batch_id=101
GET /api/business-data/oee?connection_id=schedule_readonly&device_id=FURNACE-01
```

## 安全边界

- 业务适配层只使用 GET 接口。
- 外部查询在数据源连接层再次检查，只允许单条 `SELECT`/`WITH` 查询。
- 禁止 `INSERT`、`UPDATE`、`DELETE`、`DROP`、`ALTER`、`TRUNCATE`、`CALL` 等关键字和多语句执行。
- 连接配置中的 `readOnly` 对外部数据源固定为 `true`。
- 仍建议在排产系统数据库侧创建最小权限账号，应用层防护不能替代数据库权限。

## 设计器使用建议

数字孪生视角仍以PLC实时状态为主；外部业务数据作为低频辅助面板：

- 设备详情：当前批次、工艺步骤、进度。
- 设备透视/部件详情：最近批次、温度/碳势历史摘要。
- 车间/产线总览：日运行统计、利用率、报警次数。
- 能耗、维护等区块只有在排产系统提供稳定字段和数据字典后再启用。

不要在数字孪生大屏中复制排产系统的编辑、派工、配方下发或维护工单功能。
